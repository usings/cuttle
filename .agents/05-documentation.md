# Documentation

Scale checks to the behavior a reader will follow.

- Organize around the reader's task; keep steps for one operation connected. Put prerequisites first and explain placeholders, outcomes, failures, and cleanup where relevant.
- Ground commands, defaults, outputs, and compatibility claims in current project evidence. Distinguish verified behavior from unexecuted examples.
- Give shared details one canonical home and link to it. Preserve working links, heading anchors, and examples unless a change is required; edit the source of generated documentation.
- Follow the target renderer and established terminology. Use semantic Markdown, accurate code fences, and accessible alternatives to diagrams.
- Remove filler, repetition, and inflated claims without losing technical distinctions or necessary caveats.
- Check affected snippets, links, anchors, and rendering where practical. Report unexecuted examples and static-only verification.
